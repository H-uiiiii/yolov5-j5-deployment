# CAN 总线协议定义

> 推理结果通过 SocketCAN 输出到车载总线，采用标准数据帧（11位 ID，8字节数据）。

---

## 帧类型总览

| CAN ID | 帧名称 | 用途 | 发送频率 |
|--------|--------|------|---------|
| `0x100` | 目标信息帧 1 | 类别、置信度、左上角坐标 | 每个目标 1 帧 |
| `0x101` | 目标信息帧 2 | 右下角坐标 | 每个目标 1 帧 |
| `0x102` | 结束帧 | 目标总数 + 结束标志 | 每次推理 1 帧 |

---

## 帧格式详解

### 0x100 — 目标信息帧 1

| 字节 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 0 | target_idx | uint8 | 目标序号（从 0 开始） |
| 1 | class_id | uint8 | COCO 类别 ID（0=person, 2=car, ...） |
| 2 | confidence | uint8 | 置信度 × 100（范围 0-100） |
| 3 | x1_low | uint8 | 左上角 x 坐标低字节 |
| 4 | x1_high | uint8 | 左上角 x 坐标高字节 |
| 5 | y1_low | uint8 | 左上角 y 坐标低字节 |
| 6 | y1_high | uint8 | 左上角 y 坐标高字节 |
| 7 | frame_type | uint8 | 固定 `0x01`（帧类型标识） |

坐标编码：uint16 小端模式，`x1 = x1_low | (x1_high << 8)`，范围 0-65535。

### 0x101 — 目标信息帧 2

| 字节 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 0 | target_idx | uint8 | 目标序号（与 0x100 对应） |
| 1 | x2_low | uint8 | 右下角 x 坐标低字节 |
| 2 | x2_high | uint8 | 右下角 x 坐标高字节 |
| 3 | y2_low | uint8 | 右下角 y 坐标低字节 |
| 4 | y2_high | uint8 | 右下角 y 坐标高字节 |
| 5 | reserved | uint8 | 保留（0x00） |
| 6 | reserved | uint8 | 保留（0x00） |
| 7 | frame_type | uint8 | 固定 `0x02`（帧类型标识） |

### 0x102 — 结束帧

| 字节 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 0 | total_count | uint8 | 本次推理检测到的目标总数 |
| 1-7 | end_marker | uint8[7] | 固定 `0xFF`（结束标志） |

---

## 数据解析示例（接收端）

```cpp
// 接收到 0x100 帧
uint8_t idx = frame.data[0];
uint8_t class_id = frame.data[1];
float conf = frame.data[2] / 100.0f;
uint16_t x1 = frame.data[3] | (frame.data[4] << 8);
uint16_t y1 = frame.data[5] | (frame.data[6] << 8);

// 接收到 0x101 帧（用 idx 匹配）
uint16_t x2 = frame.data[1] | (frame.data[2] << 8);
uint16_t y2 = frame.data[3] | (frame.data[4] << 8);

// 接收到 0x102 帧
uint8_t total = frame.data[0];  // 知道一共发了多少个目标
```

## candump 验证示例

```
vcan0  100   [8]  00 02 47 F0 00 23 01 01
vcan0  101   [8]  00 B9 01 FF 01 00 00 02
vcan0  100   [8]  01 00 3D 52 01 39 01 01
vcan0  101   [8]  01 85 01 62 01 00 00 02
vcan0  102   [8]  02 FF FF FF FF FF FF FF
```

**解析**：
- 目标 0：class=2(car), conf=0x47=71%, x1=0x00F0=240, y1=0x0123=291, x2=0x01B9=441, y2=0x01FF=511
- 目标 1：class=0(person), conf=0x3D=61%, x1=0x0152=338, y1=0x0139=313, x2=0x0185=389, y2=0x0162=354
- 结束：共 2 个目标

## 设计说明

1. **为什么用双帧？**
   CAN 标准帧只有 8 字节数据。一个目标需要 idx(1) + class(1) + conf(1) + 4个坐标(8) = 11 字节，超过 8 字节，因此拆成两帧。

2. **为什么坐标用 uint16？**
   640×640 图像坐标最大 640，uint8（0-255）不够，uint16（0-65535）足够且留有余量。

3. **为什么用小端？**
   x86/ARM 都是小端架构，接收端直接 `memcpy(&x1, &data[3], 2)` 即可，不需要字节序转换。

4. **frame_type 字节的作用**
   用于校验和帧类型识别。如果接收端收到 0x100 但第 7 字节不是 0x01，说明数据损坏或错位。

5. **结束帧的作用**
   接收端通过 0x102 的 total_count 知道本次推理是否完整接收。如果收到的目标数不等于 total_count，说明有帧丢失。
